# spree-shipstation Spree 6 Port Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Port `spree-shipstation` to Spree 6 as gem version 6.0.0 without changing anything ShipStation or the merchant has configured.

**Architecture:**
- A plain `ActionController::Base` controller serves the two Custom Store endpoints. It resolves the store from the active ShipStation integration.
- A query object selects the fulfillments Spree will let ship. The existing presenters render them as the same XML.
- `ShipmentNotice` resolves a fulfillment by its stored or derived number and ships it through `Spree.fulfillment_fulfill_workflow`.

**Tech Stack:**
- Ruby ≥ 3.3, Rails 8.1, Spree 6.0 (`spree_core`).
- pagy 43, Builder XML.
- RSpec with `spree_dev_tools` 1.0.0.beta2, `rspec-xsd`, sqlite dummy app.
- StandardRB, Brakeman, bundler-audit.

**Spec:** `docs/superpowers/specs/2026-10-30-spree-6-port-design.md`

- Public repo: all code, comments, specs, docs and commit messages carry generic information only. Commits are authored `Matthew Kennedy <m.kennedy@me.com>` (the worktree is configured and signs through 1Password; never override it or pass `--no-gpg-sign`). End every commit message with:

- Zero deprecation warnings. Spree 6's regenerated test app raises on its disallowed deprecations and on missing translations. Use:

  - `delivery_method`, `delivery_total`;

- Never pass `force:` or `items:` to `Spree.fulfillment_fulfill_workflow`.
- No decorators of core models.
- Repo conventions (`CLAUDE.md`): StandardRB (`bundle exec standardrb`), YARD `##` blocks on public classes and methods, one expectation per example.
- Commands, all run from the worktree `~/Developer/spree-shipstation-spree6` with bash:

  - `SPREE_VERSION=6.0.0 bundle update spree` pins Spree 6.0.0, and `bundle update spree` resolves the newest. `Gemfile.lock` is untracked.

## Review Focus

These failure modes no task's ordinary tests would exercise. Each is pinned by a test in the task named.

1. **A ship notice for a parcel exported before the upgrade.** It carries a stored 5.x number such as `H12345678901`, and must fulfil that parcel (Task 5).
2. **An order number that itself contains `-F`**, such as `SHOP-F9`. Its first parcel `SHOP-F9-F1` must resolve to that parcel, not fail or pick another (Task 5).
3. **A ship notice naming another store's parcel** must answer 400 "Could not find shipment", never ship it (Task 5).
4. **A retried ship notice for a parcel already shipped, with a different tracking number,** must correct the tracking, answer success, and send no second shipped email (Task 5).
5. **An order with two parcels, one shippable and one backordered,** exports only the shippable one, numbered by its real position (`-F1` or `-F2`) (Task 3).
